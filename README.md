# エスピクトスクール — 「すっげ〜」版ランディングページ

`../service-page/` の内容（文言・注記・承認済み画像）をそのまま使い、見せ方とインタラクションを作り直したページです。
ビルド不要の静的サイトです（HTML / CSS / JavaScript のみ）。外部ライブラリは、日本語の改行位置を整える BudouX（Apache License 2.0、`js/vendor/`）だけです。

## 見かた

- `index.html` をブラウザで直接開けば表示できます。
- ローカルサーバーで見る場合: `python3 -m http.server 8000`（このフォルダで実行）→ http://localhost:8000/

## 仕組みの図の比較（A / B / C）

「仕組み」セクションの上にある **比較用** のボタンで、図のデザインを切り替えられます。

| 案 | 内容 |
| --- | --- |
| A カード | 3つのカードを矢印でつなぐ形（最初の版） |
| B ループ | エスピクトスクールを中心にした「∞」の形。黄色い点が届ける流れ、青い点が集まる流れ |
| C イラスト | 元ページの公式イラスト（関係図）に、番号付きの流れの説明を添えた形 |

- URLの末尾に `?scheme=b#support` のように付けると、その案を開いた状態で共有できます（`a` / `b` / `c`）。
- 案が決まったら、`index.html` の `scheme-switch` のブロックと、使わない `scheme-variant` を消してください。

## 声・作品・数字の差し替え

### 本物の声（掲載の許可が出たら）

ヒーロー（最初の画面）の相談ボタンの下に、本物の利用者さんの声の枠があります（「楽しくて、やりがいがあった」／Web制作を体験した利用者さん）。掲載の許可が出るまで表示しません。

- 表示する：`index.html` の `<figure class="voice-real" data-voice-real="off">` の `off` を `on` に変えます。これだけです。
- 隠す：`on` を `off` に戻します。
- 本物の声なので「イメージ」の印は付きません。作った声（各セクションの吹き出し）とは別に、いちばん目立つヒーローに出ます。小さいスマホ（320×568）と横向きのスマホでは、最初の画面の下の端に枠の上の部分が見え、少しスクロールすると全体が見えます。
- 文言を変えるとき：同じ枠の中の `voice-real__text`（声）と `voice-real__who`（どなたの声か）を書き換えます。

### 声（吹き出し・イメージ）

- 各セクションの吹き出しは、依頼者が選んだ11個の声です（5回目の依頼）。本物かどうかの確認がまだなので、広告の決まりに合わせて、必ず小さく「イメージ」（`voice__tag`）を付けています。消さないでください。
- 「楽しくてやりがいがあった」は本物の声の枠と同じ言葉なので、吹き出しには使わず、本物の枠（上）だけに置いています。
- 職員さんの声のうち2つは、意味を変えずに「安心できる」言い方に寄せています（「提出の確認をしてもらえるので、安心して他の支援に回れる」「ITに詳しい職員がいなくても、安心して始められた」）。
- 置き場所：01 スクールについて（2つ）、02 活用イメージ、03 学びと記録、提出の瞬間と、残る記録、作品の壁（2つ）、05 役割、06 仕組み、07 案件の進め方、08 導入の流れ。
- 利用者さんの声（`voice--user`）は左から、職員さん・管理者さんの声（`voice--staff`）は右から話す形で出ます。1つだけのセクションでも同じです。
- 文言は `index.html` の `class="voice"` の中です。変えるときは短く（スマホで2〜3行まで）。
- 本物の声を出すときは、吹き出しの「イメージ」を消すのではなく、上の「本物の声」の枠を使ってください。

### 納品までの流れ（課題チャットの見本）

- 文言は、依頼者とベータが決めたものです（7回目）。そろえている言葉：「成果物」「提出」「エスピクトのスタッフ」「利用者さん」。使わない言葉：「作品」「担当」「返事」「あなた」、見出しでの「届きました」。
- 手順とチャットの組み合わせ：1 取り組む ＝ 質問とぴくとの答え、2 提出 ＝ 提出、3 チェック ＝ 直す所と出し直し、4 納品 ＝ 「納品しました」。`index.html` では、手順ごとの `li.flowline__step` の中に、手順の札（`flowline__card`）と、その部分のチャット（`chat`）が入っています。
- チャットの見た目は、アプリの相談画面に合わせています（利用者さんの文は右の青い吹き出し、ぴくととエスピクトのスタッフは左の灰色の吹き出しとアイコン。ぴくとは角帽のアイコン、スタッフはロゴ）。ぴくとの答えに付いている「指示書の見本」の小さな絵は、画像ファイルを使わず CSS で描いています（見出しのすぐ下の写真の位置を、オレンジの枠で示しています）。
- 見本の文には「イメージ」を付けています。書かないこと：返事が来るまでの時間の約束（「◯時間以内」など）、「AIが自動で判定・採点する」など今ない機能、作った数字。
- 「納品しました」がこのまとまりのゴールなので、チャットの中でいちばん大きな文字にし、緑の地にしています。
- 見た目（8回目）：見出しと流れは、全幅の緑の帯（白い点の模様、斜めの下端、右に白と黄の帯）の上にあります（`.sent-band`。「案件の進め方」の水色の帯と同じ作り）。記録の見本と「記録がきちんと残る」は、帯の下の明るい背景のままです。
- 見出しの「納品まで。」は白い札、手順は番号の丸・色つきのアイコン・白いカード（読んでいる手順は番号が黄色）、手順4（納品）は届くと黄色いカードに星が2つ付きます。
- 右の見本は、黒い枠のスマホ（上にカメラ、下にホームバー）で、アプリの青い見出しの帯、白い吹き出し、ぴくとの青い丸いアイコン。「納品しました」は緑のグラデーションに紙ふぶきの点。
- 広い画面（1200px 以上）では、手順1の下の空いた所に、じゃっぷちゃん（`jappu-pointing.webp` を左右反転。最初の画面と同じ画像なので、読み込みは増えません）がチャットを指しています。手順1が読まれると出てきます。
- スマホ（9回目。幅 719px 以下、または高さ 500px 以下で幅 1023px 以下の横向きスマホ）は短い版です：手順ごとに1枚のカードの中に、その部分のチャットの抜粋を小さく入れます。吹き出しは5つ（出し直しとOKの返事は省き、手順の文で伝えます）。指示書の見本は、ぴくとの答えの横の小さな絵です。「納品しました」は一番大きいままです。このまとまり（緑の帯）の長さは、390×844 で約1590px（画面約1.9つ分）です。PC・タブレットは8回目の見た目のままです。
- 省いた吹き出しは HTML には残っていて（PC で表示）、スマホでは表示しないだけです。`js/main.js` は、表示していないメッセージを、その手順と一緒に出たことにします。
- 幅 1024px 以上で高さ 500px 以下の画面では、手順のカードを行の上（その部分の最初のメッセージの横）に置きます。カードが画面に全部入ってから光るようにするためです。

### 記録の見出し（記録の見本のすぐ後）

「記録がきちんと残る。だから、安心して見せられる。」のまとまりです。依頼者が強く出したい所なので、価値（行政の指導や監査、ご家族への説明にも見せられる）を大きく、国の検討の話は下に小さく書いています。

- 「今から」：提出した成果物と提出の時刻／確認した人と確認の時刻。
- 「11月中旬から」：取り組み記録（ログインから「おわる」までを時刻つきで記録／あとから書き換えできない形で保存／見られるのは事業所の職員だけ／PDF・CSVで出せる）。
  - 取り組み記録が始まったら、`index.html` の `trust-group--next` の「11月中旬から」を「今から」に変えてください（2つのまとまりはそのままで大丈夫です）。
- 下の小さな注記は、厚生労働省の検討チームの資料（2026年9月28日）をもとにした、2026年10月時点の内容です。在宅での支援に限った話で、案の段階です。決まったときや内容が変わったときは、`trust__note` の文を書き換えてください。制度名や条文番号は書かない、断定しない、という書き方にしています。

### 作品の壁（取り組める仕事の下）

利用者の方が作り、依頼主に納品した作品を並べる場所です。今は掲載の許可が出た本物の作品が無いので、ページ内の制作イメージ画像で形だけ作り、全部に「制作イメージ」と出しています。

本物の作品に差し替える手順：

1. 画像を横 1200px 程度の WebP に圧縮して `assets/img/` に置きます（目安 150KB 以下）。例：`ffmpeg -i 元の画像.png -vf scale=1200:-1 -c:v libwebp -quality 72 assets/img/wall-01.webp`
2. `index.html` の `class="wall__item"` の中の `img`（`src`・`alt`・`width`・`height`）、`wall__cat`（分野）、`wall__title`（作品名）を書き換えます。見せる位置は `style="object-position: 横% 縦%"` で調整できます。今の制作イメージは、絵の一部を少し拡大して見せています。本物の作品を全体で見せたいときは、画像を横:縦＝4:3 で作り、`style` に `transform: none;` を足してください（例：`style="object-position: 50% 50%; transform: none;"`）。
3. 依頼主に納品済みで、掲載の許可が出た作品だけ、`<li class="wall__item" data-reveal>` に `data-delivered` を足します（`<li class="wall__item" data-delivered data-reveal>`）。「依頼主に納品済み」の印が出て、「制作イメージ」の文字が消えます。
4. 全部を本物にしたら、見出しの下の「いまは制作イメージを並べています。」を消します。

「納品済み」の印は `data-delivered` を付けた作品にしか出ません。

### 今月の数字（`data/stats.json`）

「提出の瞬間と、残る記録」セクションに、今月の数字（届いた成果物・授業・納品）の枠があります。数字は `data/stats.json` から読み、**数字が入っている項目だけ**表示します。今は全部 `null`（数字なし）なので、枠ごと表示していません（作り話の数字は出しません）。

```json
{ "label": "今月の取り組み", "note": null, "submissions": null, "lessons": null, "deliveries": null }
```

| 項目 | 表示 |
| --- | --- |
| `submissions` | 届いた成果物 ○件 |
| `lessons` | 授業 ○回 |
| `deliveries` | 納品 ○件 |
| `label` | 枠の見出し（例：「11月の取り組み」） |
| `note` | 数字の下の小さな注記（例：「エスピクトスクール全体の数字です（11月30日時点）」）。不要なら `null` |

更新の手順：

1. `data/stats.json` の数字を書き換えます（半角の整数。まだ分からない項目は `null` のまま）。
2. `label` を「11月の取り組み」のように変え、必要なら `note` に集計の範囲や日付を書きます。
3. このファイルだけをアップロードし直します。`index.html` などを変える必要はありません。

- 数字が1つも無い・ファイルが無い・読めないときは、枠ごと出ません。0 以上の数字だけ表示します（マイナスや文字は出ません）。
- 画面に入って少し見ていると、0 から数え上がります（動きを減らす設定では、最初から最後の数字）。
- `index.html` をファイルとして直接開いた場合（`file://`）は、ブラウザの制限で読み込めないため出ません。サーバーに置いたときに出ます。

### 記録の見本

- 「記録の見本（架空）」と書いた、架空のデータの見本です。氏名と成果物のリンクはぼかしています（読み上げでは「ぼかし」と伝えます）。
- 本物の記録の画面に差し替えるときも、氏名・リンクなど個人が分かる所は必ずぼかしてください。

## 画面サイズへの対応

- スマホ（320〜430px）、スマホ横向き、タブレット（縦・横）、ノートPC、デスクトップ（〜2560px）で、それぞれ見やすい配置に切り替わります。
  - スマホ横向きなど背の低い画面では、最初の画面が「見出し・説明・ボタン」と「キャラクター」の横並びになります。
  - スマホと縦向きのタブレット（1024×1366 など）は縦並びの配置で、相談ボタンが最初の画面に入るよう、見出しのすぐ下に置いています。
  - タブレット（〜999px）では、ケースの切り替えを「表示中／見る」付きのボタン型カードにしています。案件の進め方は 2×2 の並び（スマホでは縦の一覧）です。最後のセクションは 768px から文字とキャラクターの横並びです。
  - 1199px までは、活用イメージのケースを1列にし、「こんな課題」のカードは文字とキャラクターの横並びにしています。
  - 本文の幅は 1240px です。1800px 以上の画面では 1400px、2200px 以上では 1600px に広げます。ヘッダーとフッターの大きなロゴ文字も、この幅にそろえています。
  - 背の低いノートPC（高さ760px以下）では、最初の画面の手書き風のひとことを省いて、窮屈にならないようにしています。
  - 紹介動画は、どの画面でも画面の高さに収まる大きさで表示されます。
- 日本語は、文節（意味のまとまり）の切れ目でだけ改行します（BudouX）。そのうえで次のルールを足しています（`js/main.js` の「phrase fix-ups」）。iOS 18 以前の Safari のように `text-wrap: pretty` に対応していないブラウザでも同じ結果になります。
  - 語の途中で切らない：カタカナ語（ショー／ト）、4文字までの漢字の熟語（質問／対応）、「取り組む」などの複合動詞、「エスピクトAI」「福祉サービス」のような文字の種類が変わる複合語、「と／して」「の／方」。
  - 行頭に「、。」）/」、行末に「「（」が来ない。「（1分32秒）」「「できる」を」のような短いかっこ書きは一続きにする。
  - 「20:00〜」「2026.10.01」のような数字は途中で切らない（Safari は「:」の後で改行することがあるため）。
  - 「企業・商品の」のような「・」を含む短い語句は途中で切らない（長い列挙は「・」の後で改行してよい）。列挙の最後が「課題の提出」のように次の語句へ続くときは、その語までつなげる（`js/main.js` の `TERMS`）。
  - 最後の行に1〜3文字だけ残らないよう、短い最後の文節は前とつなげる。
  - 枠より長い語句だけは、「・」の後、かっこの前後、文字の種類が変わる所（投稿｜スケジュール など）で改行できるようにする。この判定は枠の幅が変わるたびにやり直します。

## 動き・演出の見せ方（読んでいる間に見えるように）

スクロールの途中で演出が画面の外で起きて「見えないうちに終わる」ことがないよう、次の決まりで動かしています（`js/main.js`）。

- **読む位置に合わせる**：導入の流れのキャラクターは、ヘッダーの下の見える範囲のちょうど真ん中（読んでいる高さ）にいて、スクロールした分だけ道を進みます。最初のステージより手前では最初の点で待ち、最後の点の先では止まります。スマホの「案件の進め方」の書類アイコンも同じ決まりです。
- **横に進む演出は、全体が見えている間に**：PCの「案件の進め方」は、線が画面の下の方から上の方へ動く間に書類アイコンが端から端まで進みます。タブレットの 2×2 の並びでは、各 STEP はアイコンが画面の中ほどまで来たときに光ります。
- **1回だけの演出は、少し見ていてから**：制作ボードの自動再生は、ボードが半分以上見えていて、ページの動きが落ち着いている（0.15秒）ときに始まります。金額のカウントアップは、金額全体が0.35秒見えていたときに始まります。どちらも、メニューから移動する途中や速いスクロールで通り過ぎただけでは始まりません。制作ボードは、各パーツが画面に見えているときにだけ次へ進み（0.6秒おき）、最後に「完成！」のスタンプを押します。読み進めてボードが画面の上の方へ流れ始めたら、残りを早めに進めます。始まったあとは、読む速さのスクロール（ホイール1回分・ページ送り）の間も続きを進め、速いスクロールやメニュー移動の途中だけ止まります。画面から外れると止まり、戻ると続きから進みます。カウントアップは途中で画面から外れたら最後の値を表示し、次に見たときにもう一度数えます。
- **「順番に見る」ボタン**：ボードが画面に入るように先にスクロールしてから組み上げます（スマホ・タブレットではボタンの下にボードがあるため）。
- **アプリ紹介**：最初の章を読み始めるときに右の画面が全部見えているよう、また最後の章を読み終えるまで画面が上へ押し出されないよう、章の上下に余白を取っています（画面の高さに合わせて自動で計算）。
- **仕組みの図（案B）**：スマホでは図全体が画面に収まるよう、画面の高さに合わせて間隔を詰めます。背の低い画面（720px 以下）では部品を小さくし、横向きスマホでは3つを横に並べます。
- **ふわっと表示**：短い見出しやボタンは、半分くらい見えた時点で表示します（背の低い画面で、画面の下端に見えているのに空白のまま、を防ぐため）。
- **納品までの流れ**：チャットの各メッセージは、読む位置（ヘッダーの下の見える範囲の6割の高さ）を通ったときに出ます（背の高いものは、全部が画面に入ってから）。読んでいる手順は、手順の札が読む位置に来たとき、またはその部分の最初のメッセージが出たときに切り替わり、番号の間の線がそこまで伸びます。その部分のチャットははっきり表示され、前の部分は次の部分が出始めたときに少し薄くなり、まだの部分は薄く待っています（チャットが空に見えることはありません）。広い画面では、読んでいる手順からその部分へ点線がつながり、その部分の背景が薄い緑になります。「納品しました」は、出たときにチェックが弾み、輪が一度広がります。上へ戻ると逆の順に戻ります。
- **アプリ紹介の画面の切り替え**：新しい画面が小さな四角で全部そろったあと、下の画像を一瞬で入れ替えてから、同じ瞬間に四角を外します（以前は、入れ替えを0.35秒かけてしていたため、四角が外れた瞬間に前の画面が戻っていました）。切り替えの途中で読む人がさらに次の章へ進んだ時は、今の切り替えをその場で終えてすぐ次へ、始まる前に進んでいた時は間の画面を飛ばします。境目で上下に行ったり来たりした時は、今の切り替えを終えてから戻ります。確かめ方は `../qa/README.md` の `flickvid.mjs`。
- **吹き出しの声**：画面に入ったときにふわっと出て、ゆっくり揺れます。PC（1280px 以上）では見出しのすぐ上の左右の端に、それより狭い画面では見出しの上に置いています。
- **動きを減らす設定**：導入の流れ・案件の進め方は最初から全部光った状態、制作ボードは最初から完成形、金額と今月の数字は最初から最後の値、納品までの流れの手順とチャットは最初から全部はっきり表示します（薄くしたり、一部だけ目立たせたりしません。中身がそのまま読めます）。

## 固定ボタン

- 「LINEで相談」ボタンは、最初の画面（ヒーロー）と最後の相談ボタンの所では表示しません（同じボタンがすぐ近くにあるため）。また、下へ読み進めている間は隠れ、上へスクロールしたときに表示されます。読んでいる文章の上に重ならないようにするためです。常に表示したい場合は、`js/main.js` の「floating LINE button」の部分で `is-tucked` を付ける処理を消してください。
- 動きを止めるボタンは、画面の下に浮かせるのをやめて、ヘッダー（768px 以上）とメニューの中（「表示の設定」）に置いています。

## 素材と文言

- 文言・注記（「モデルケースであり実績ではない」「金額は案件額であり工賃ではない」など）は元ページのまま使っています。新しい実績や数字は加えていません。

## フォント

- Noto Sans JP / DM Sans: 元サイトと同じサブセット（`css/fonts.css`）
- 日本語の見出しは Noto Sans JP の極太（900）です。読みやすさを優先して、太いディスプレイ書体は日本語には使っていません。
- Dela Gothic One: 数字と英字のアクセント（「1:32」「5万〜60万円」「01」など）だけに使っています。ASCIIの範囲だけのサブセットで、`css/style.css` にデータURLとして埋め込んでいます（`file://` で開いても読み込めるように）。
- Yomogi（手書き風のひとこと「つくる。届ける。つながる。」）: ページで使う文字だけのサブセットです。
- どちらも SIL Open Font License 1.1 です（ライセンス文は `assets/fonts/`）。
